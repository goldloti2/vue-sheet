# 搜尋、篩選與排序

列表頁的搜尋、篩選與排序如何接上與運作。使用者看到的外觀與操作見 [design/list.md](../design/list.md)。

---

## 搜尋

頁面登記後，App Bar 才出現放大鏡；按下後整條 App Bar 換成「←＋輸入框」，標題與動作暫時讓位。

**列表頁不需自行串接**：`useListPage(table, schema)` 內部已完成登記，回傳的 `rows` 即為篩選與搜尋後的結果。其內部以 `useListControls` 登記一條搜尋字串（頁面的 ref），再以 `useSearch` 依該字串過濾；自行組成版面時，依同樣的方式串接。

- **有登記才有放大鏡**，實務上只有列表頁會出現；詳細頁與表單頁不放
- **`query` 為頁面的 ref**：`AppShell` 僅負責讓使用者輸入，過濾由頁面自行處理
- **比對 `schema.searchable` 中的 `text` 與 `ref` 欄位**（真實與虛擬欄位皆可，`ref` 比對的是父列的名稱）；同一份清單中的其他型別歸篩選抽屜
- **分詞**：依空白切分，以雙引號包住的部分視為一個詞，每個詞皆須符合（AND）
- **一律轉為小寫比對**，不做全形與半形的正規化
- **效能**：每列可搜尋的文字僅於 `rows` 改變時重算，輸入時只執行 `includes`
- **換頁時自動收起**；回到仍帶有 `query` 的頁面（KeepAlive）時自動重新開啟
- **有頁籤的頁面**：各頁籤的列表放在 `TabPage` 中時，搜尋字串由 `TabPage` 統一登記，跨所有頁籤共用（見下方「同一頁面中的多張表」）

---

## 篩選

登記時另給 `{ tables: [{ schema, filters, rows }] }`，輸入框內的最右側即多出一顆篩選鈕（有條件生效時為主色），按下後自右側滑出抽屜。`useListPage` 已連同篩選一併登記：每張表一份 `filters`，與未過濾的整表一同交給 `useListControls`，資料再依序經過 `useFilter` 與 `useSearch`。

順序固定為：**整表 → `useFilter` → `useSearch` → 畫面**。篩選抽屜的選項依整表（`allRows`）列出。

- **修改後即時生效**，沒有套用鈕；按 ← 關閉搜尋時，篩選一併清除
- **篩選的對象為 `schema.searchable` 中的 `select`、`boolean`、`number`、`date`、`duration`**（`text` 與 `ref` 歸搜尋，兩者共用同一份清單）
- **不同欄位之間為 AND，同一欄的多個選項之間為 OR**
- **範圍條件**（`number`、`date`、`duration`）只填一邊即為單邊的限制；值為空的列一律排除。時長換算為秒後比較
- **`select` 與 `boolean` 另有「(空白)」**，勾選後才保留值為空的列
- **選項僅列出 `rows`（未過濾的整表）中出現過的值**，資料改變時選項隨之改變

### 抽屜分為兩層

| | 內容 |
| --- | --- |
| **第一層** | 可篩選欄位的清單，順序即 `schema.searchable` 的順序，略過歸搜尋列的 `text` 與 `ref`。已有條件的欄位，名稱下方以小字顯示目前的條件（例如 `≥ 100`、`100 ～ 500`、`2026/01/01 ～`；`select` 為所選值的串接，過長時截斷並加上「…共 X 項」），右側顯示一個主色的圓點。「清除」位於這一層，清除整張表的條件 |
| **第二層** | 點選一欄後進入，填寫條件：`select` 為一列一項的勾選框（「(空白)」排在最後），`boolean` 同樣為勾選框，選項為是、否與「(空白)」；`number`、`date`、`duration` 為兩格的範圍。按 ← 回到第一層 |

關閉抽屜時亦回到第一層。抽屜開啟時 `PageFab` 會讓開，由 `useOverlay` 的 `overlayOpenKey` 通知。

抽屜連同背後的遮罩覆蓋整個畫面，**開啟時無法操作 App Bar 上的任何東西**（包括搜尋列與 ← 關閉），須先關閉抽屜。右側抽屜由篩選與排序共用，一次只顯示其中一種。

### 同一頁面中的多張表

**將各列表放入 `TabPage` 的頁籤即可，不需另行登記**（見 [TabPage.md](../components/panel/TabPage.md)）；同時顯示多個列表時放入 `DashboardPage` 的面板，行為相同（見 [DashboardPage.md](../components/panel/DashboardPage.md)）。`TabPage` provide 一份「共用的列表控制」（`useSharedListControls`），其中的 `useListPage` 不自行登記，改為加入此控制：

- **搜尋字串共用一條**：輸入一次，各頁籤的列表皆隨之過濾
- **同一張表共用一份篩選與排序**：例如各頁籤為同一張表依狀態切分的列表（以 `useListPage` 的 `scope` 只留該狀態的列），條件套用於所有頁籤，抽屜中該表只有一個 chip
- **不同的表各有一份**，同時生效；抽屜第一層的上方多出一排表的 chip
- **其中沒有列表時不登記**，App Bar 不出現放大鏡
- 頁籤的值與某張表的 `tableLabel` 相符時，抽屜開啟時先停在該表

抽屜的行為：

- **第一層的上方有一排表的 chip**（標籤為 `schema.tableLabel`），決定目前編輯哪一張表；只有一張表時不顯示。關閉抽屜即重置，下次開啟時重新依頁籤決定
- **篩選鈕的主色標示涵蓋所有表**；「清除」僅清除目前的那一張，全部清除須按 ←（關閉搜尋）
- **排序面板使用同一批表**（僅列出可排序者），chip 亦為同一排

**同一張表依狀態切分的頁籤頁**：將列表拆成只供引用的元件，置於該表資料夾的 `_ref/`（不產生路由），以 `scope` 只留該狀態的列；頁籤頁僅保留 `TabPage`，每個頁籤放一個列表並傳入狀態。`scope` 位於篩選與搜尋之前，各頁籤僅比對各自的部分。FAB 屬於列表，新增時預設的狀態直接取自傳入的狀態；同一個列表放入儀表板時不傳入狀態，即為整張表。範本見 `template/pages/tab-list.vue` 與 `template/pages/_ref/list.vue`。

**拆出的列表以 props 接受條件**，同一個元件可用於不同頁面，例如另一頁只列出某一種狀態。常用且意義固定的條件宜定為專屬的 prop（例如 `status`）；需要任意條件時，另提供通用的 `scope` prop，於元件內與專屬的條件合併。

**不使用 `TabPage` 時，由頁面手動登記**：各表的 `useListPage` 關閉自動登記，並共用頁面建立的一條搜尋字串，由頁面以 `useListControls` 一次登記全部的表。寫法見 [ListPage.md](../components/page/ListPage.md#手動登記多張表)。

## 排序

列於 `schema.sortable` 的欄位即出現在排序面板中，**面板上的順序即該清單的順序**。`useListPage` 已將 `sort` 一併登記，列表頁不需另外撰寫，App Bar 的放大鏡右側即多出一顆排序鈕（不是預設的排序時為主色）；按下後開啟的是**與篩選同一個右側抽屜**。

- **一次只依一欄排序**：點選一欄即依該欄排序，再點同一欄切換遞增或遞減，右側的箭頭顯示目前的方向。不提供多層排序
- **`schema.defaultSort` 一律接在後面作為 tiebreaker**，同值的列因此保持穩定的順序
- **「清除」回到 `defaultSort`**，位置與外觀與篩選的「清除」相同；未選擇排序時，清單中沒有任何一列被標示
- **修改後即時生效**，沒有套用鈕
- **重新整理後回到預設**，不保存設定（與篩選的標準相同）
- **`image` 不能排序**，即使列於 `sortable` 亦會略過

比較方式大致為依值排序，以下兩種型別例外：

| 型別 | 排序依據 |
| --- | --- |
| `ref` | 對方的 `$label` |
| `select` | `options` 的宣告順序。`options` 中沒有的值（`allowCustom` 時自行輸入者）一律排在最後 |
| `boolean` | 否在前、是在後 |
| 其他 | 欄位的值；`duration` 換算為秒、`date` 比較時間；空值不論遞增或遞減一律排在最後 |

**排序與分組只能擇一**，由頁面自行判斷，框架不介入：`useListPage` 回傳的 `sort` 有值時，交給 `ListPage` 的是 `rows` 而非 `groups`（寫法見 [ListPage.md](../components/page/ListPage.md#分組與頁籤)）。

排序改變時，`ListPage` 發布給 `useListOrder` 的順序隨之改變，詳細頁的上下一筆與左右滑動因此自動與畫面一致。
