# 搜尋、篩選與排序

列表頁的搜尋、篩選與排序的接法與運作方式。使用者看到的外觀與操作見 [design/list.md](../design/list.md)。

---

## 搜尋

頁面登記後，App Bar 才出現放大鏡。按下放大鏡後，整條 App Bar 換成「← 與輸入框」，標題與動作暫時隱藏。

**列表頁無須自行串接**：`useListPage(table, schema)` 內部已完成登記，回傳的 `rows` 即為篩選與搜尋後的結果。
- `useListPage` 內部以 `useListControls` 登記一條搜尋字串（頁面的 ref），再以 `useSearch` 依該字串過濾
- 自行組合版面時，依同樣的方式串接

搜尋的規則：
- **有登記才有放大鏡**，實際上只有列表頁出現。詳細頁與表單頁不放置
- **有搜尋字串或任一張表有篩選條件時，放大鏡為主色**
- **`query` 為頁面的 ref**：`AppShell` 只負責讓使用者輸入，過濾由頁面自行處理
- **比對 `schema.searchable` 中的 `text` 與 `ref` 欄位**：真實欄位與虛擬欄位皆可，`ref` 比對父列的名稱。同一份清單中的其他型別屬於篩選抽屜。沒有可搜尋欄位的表不受搜尋影響，維持全部的列
- **分詞**：依空白切分，以雙引號包住的部分視為一個詞。每個詞皆須符合（AND）
- **一律轉為小寫比對**，不做全形與半形的正規化
- **效能**：每一列可搜尋的文字只在 `rows` 改變時重算，輸入時只執行 `includes`
- **換頁時自動收起**。回到仍帶有 `query` 的頁面（KeepAlive）時，自動重新開啟
- **有頁籤的頁面**：各頁籤的列表置於 `TabPage` 中時，搜尋字串由 `TabPage` 統一登記，跨所有頁籤共用（見下方「同一頁面中的多張表」）

## 篩選

登記時另外提供 `{ tables: [{ schema, filters, rows }] }`，輸入框內的最右側即多出一個篩選按鈕。有條件生效時，按鈕為主色。按下後，從右側滑出抽屜。

`useListPage` 已一併登記篩選：
- 每張表一份 `filters`，與未過濾的整張表一同交給 `useListControls`
- 資料再依序經過 `useFilter` 與 `useSearch`

順序固定為：**整張表 → `useFilter` → `useSearch` → 畫面**。篩選抽屜的選項依整張表（`allRows`）列出。

篩選的規則：
- **修改後即時生效**，沒有套用按鈕。按 ← 關閉搜尋時，篩選一併清除
- **篩選的對象為 `schema.searchable` 中的 `select`、`boolean`、`number`、`date`、`duration`**。`text` 與 `ref` 屬於搜尋，兩者共用同一份清單
- **不同欄位之間為 AND，同一欄的多個選項之間為 OR**
- **範圍條件**（`number`、`date`、`duration`）只填一邊時，即為單邊的限制。值為空的列一律排除。時長換算為秒後比較
- **`select` 與 `boolean` 另有「(空白)」**，勾選後才保留值為空的列
- **選項只列出 `rows`（未過濾的整張表）中出現過的值**。資料改變時，選項隨之改變

### 抽屜分為兩層

| | 內容 |
| --- | --- |
| **第一層** | 可篩選欄位的清單，順序即 `schema.searchable` 的順序，略過屬於搜尋列的 `text` 與 `ref`。<br>・已有條件的欄位，名稱下方以小字顯示目前的條件，例如 `≥ 100`、`100 ～ 500`、`2026/01/01 ～`。`select` 為所選值的串接，過長時截斷並加上「…共 X 項」<br>・已有條件的欄位，右側顯示一個主色的圓點<br>・「清除」位於這一層，清除整張表的條件 |
| **第二層** | 點選一欄後進入，填寫條件：<br>・`select` 為一列一項的勾選框，「(空白)」排在最後<br>・`boolean` 也是勾選框，選項為是、否與「(空白)」<br>・`number`、`date`、`duration` 為兩格的範圍<br>・按 ← 回到第一層 |

- 關閉抽屜時，也回到第一層
- 抽屜開啟時，`PageFab` 讓開。抽屜以 `useOverlay` 的 `overlayOpenKey` 通知 `PageFab`
- 抽屜連同背後的遮罩覆蓋整個畫面，**開啟時無法操作 App Bar 上的任何元素**，包括搜尋列與關閉用的 ←。須先關閉抽屜
- 右側抽屜由篩選與排序共用，一次只顯示其中一種

### 同一頁面中的多張表

**將各列表放入 `TabPage` 的頁籤即可，無須另外登記**（見 [TabPage.md](../components/panel/TabPage.md)）。同時顯示多個列表時，放入 `DashboardPage` 的面板，行為相同（見 [DashboardPage.md](../components/panel/DashboardPage.md)）。

`TabPage` provide 一份共用的列表控制（`useSharedListControls`）。其中的 `useListPage` 不自行登記，改為加入這份控制：

- **搜尋字串共用一條**：輸入一次，各頁籤的列表皆隨之過濾
- **同一張表共用一份篩選與排序**：例如各頁籤為同一張表依狀態切分的列表，各自以 `useListPage` 的 `scope` 只保留該狀態的列。此時條件套用於所有頁籤，抽屜中該表只有一個 chip
- **不同的表各有一份**，同時生效。抽屜第一層的上方多出一排表的 chip
- **其中沒有列表時不登記**，App Bar 不出現放大鏡
- 頁籤的值與某張表的 `tableLabel` 相符時，抽屜開啟時先停在該表

抽屜的行為：

- **第一層的上方有一排表的 chip**，標籤為 `schema.tableLabel`，決定目前編輯的表。只有一張表時不顯示。關閉抽屜即重置，下次開啟時重新依頁籤決定
- **篩選按鈕的主色標示涵蓋所有表**。「清除」只清除目前的那一張表，全部清除須按 ← 關閉搜尋
- **排序面板使用同一批表**，只列出可排序的表，chip 也是同一排

**同一張表依狀態切分的頁籤頁**：
- 將列表拆成只供引用的元件，置於該表資料夾的 `_ref/`，不產生路由。元件以 `scope` 只保留該狀態的列
- 頁籤頁只保留 `TabPage`，每個頁籤放一個列表並傳入狀態
- `scope` 位於篩選與搜尋之前，各頁籤只比對各自的部分
- FAB 屬於列表，新增時預設的狀態直接取自傳入的狀態
- 同一個列表放入儀表板時不傳入狀態，即列出整張表
- 範本見 `template/pages/tab-list.vue` 與 `template/pages/_ref/list.vue`

**拆出的列表以 props 接收條件**，同一個元件可用於不同頁面，例如另一頁只列出某一種狀態。常用且意義固定的條件，定為專屬的 prop（例如 `status`）。須接受任意條件時，另外提供通用的 `scope` prop，於元件內與專屬的條件合併。

**不使用 `TabPage` 時，由頁面手動登記**：各表的 `useListPage` 關閉自動登記，並共用頁面建立的一條搜尋字串，由頁面以 `useListControls` 一次登記全部的表。寫法見 [ListPage.md](../components/page/ListPage.md#手動登記多張表)。

## 排序

列於 `schema.sortable` 的欄位即出現在排序面板中，**面板上的順序即該清單的順序**。
- `useListPage` 已一併登記 `sort`，列表頁無須另外撰寫
- App Bar 的放大鏡右側即多出一個排序按鈕。不是預設的排序時，按鈕為主色
- 按下後開啟的是**與篩選相同的右側抽屜**

排序的規則：
- **一次只依一欄排序**：點選一欄即依該欄排序，再點選同一欄即切換遞增或遞減，右側的箭頭顯示目前的方向。不提供多層排序
- **`schema.defaultSort` 一律接在後面作為次要的排序**，同值的列因此保持穩定的順序
- **「清除」回到 `defaultSort`**，位置與外觀和篩選的「清除」相同。未選擇排序時，清單中沒有任何一欄被標示
- **修改後即時生效**，沒有套用按鈕
- **重新整理後回到預設**，不保存設定，與篩選的規則相同
- **`image` 不能排序**，即使列於 `sortable` 也略過

各型別的比較方式：

| 型別 | 排序依據 |
| --- | --- |
| `ref` | 父列的 `$label` |
| `select` | `options` 的宣告順序。`options` 中沒有的值（`allowCustom` 時自行輸入的值）排在選項之後，彼此依文字排序 |
| `boolean` | 否在前，是在後 |
| `text` | 文字，其中的數字依數值大小比較，例如「2」在「10」之前 |
| `duration` | 換算為秒後比較 |
| `date` | 比較時間 |
| 其他 | 欄位的值 |

不論遞增或遞減，空值一律排在最後。

**排序與分組只能擇一**，由頁面自行判斷，框架不介入：`useListPage` 回傳的 `sort` 有值時，交給 `ListPage` 的是 `rows`，不是 `groups`。寫法見 [ListPage.md](../components/page/ListPage.md#分組與頁籤)。

排序改變時，`ListPage` 發布給 `useListOrder` 的順序隨之改變。因此詳細頁的上一列、下一列與左右滑動，自動與畫面一致。
